### **Purpose**

### Empty States communicate the **absence of content** or results in a clear and constructive way. They guide users on what happened and, when appropriate, what they can do next.

### They replace content areas when no data is available, no results are found, or an error prevents content from loading.

### **When to use**

-  When a section has no data yet (first-time use)

-  When a search or filter returns no results

-  When content cannot load due to an error

-  When a user has not completed required setup

-  When a feature is available but currently inactive

 

### **Variants **

 **Informational Empty** Used when no data exists yet. 

### Example:

-  No transactions yet

-  No watchlist created

 

### Tone: Neutral, supportive, encouraging action.

 **No Results** Used when a search or filter returns nothing. 

### Example:

-  No results found for “Crypto”

-  No matching assets

 

### Tone: Neutral, corrective.

 Error Used when content fails to load or an issue prevents display. 

 Example:

-  Failed to load data

-  Connection lost

 

 Tone: Clear, calm, solution-oriented.

 May use Verdict styling for emphasis when appropriate.

 

 **Usage Guidelines**

 **Do**

-  Clearly explain why the content is missing

-  Use a short, descriptive title

-  Provide helpful next steps when possible

-  Include a primary CTA when user action can resolve the state

-  Keep messaging concise and human

-  Match tone to context (informational vs error)

-  Use illustration to support meaning, not distract

 

 **Avoid**

-  Blaming the user

-  Using overly technical language

-  Displaying multiple CTAs with equal weight

-  Overusing Empty States for minor gaps

-  Using an empty state when loading should be shown instead

-  Treating No Results as an error

-  Empty State is a content placeholder, not a modal, not a toast, and not an overlay.

 

 **States & Behavior**

-  Replaces content within its parent container

-  Does not create a new surface layer

-  CTA (if present) follows standard button hierarchy rules

-  Illustration is optional but recommended for large empty areas

-  Error variant may use Verdict color for emphasis

-  Empty State persists until the condition changes

-  Should be fully accessible and readable
